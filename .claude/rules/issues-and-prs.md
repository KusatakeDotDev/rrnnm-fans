# Issue と PR の書き方

出どころ: rurino-nemo-fansite#78

- **内部のタスクは Linear（チーム `rrnnm-fans`）に立てる。GitHub の Issue は、外の人から不具合の報告を受ける場所にする（`.github/ISSUE_TEMPLATE/bug.yml`）。** リポジトリを公開するので、内部の検討や作業の記録を公開の場に置かないため。出どころ: RRNNM-7
- **Linear の Issue も PR も、決まった型で書く。** 書くのはほぼエージェントで、読んで判断するのは人なので、人が読みやすい同じ型にそろえるため

  | 作るもの | 型 |
  | --- | --- |
  | Linear の Issue（やることが決まっている作業） | タイトルは何をするかだけ。見出しは「背景」「やること」「完了条件」「決めること（任意）」「範囲外（任意）」「参照」。決まっていないことは「やること」に混ぜず、「決めること」に出す |
  | Linear の Issue（何をするかを決める・メモ・構成案） | タイトルは「〜を決める」。見出しは「背景」「決めたいこと」「案」「制約（決まっていること）」「参照」。決まったら、決定は ADR に、作業はタスクの Issue に移して閉じる |
  | PR | `.github/pull_request_template.md`。API（GitHub MCP）で作るときはテンプレートが自動では入らないので、先にファイルを読んでその型で本文を組む |

- **見出しは消さない。書くことが無ければ「なし」と書く。「（任意）」の節だけは、無ければ見出しごと消す。** 書き忘れと区別するため
- **テンプレート内の `<!-- -->` は、本文に残さない。** GitHub の画面には出ないが、API で読む本文には書いたままの Markdown が返るので、エージェントには書き方の指示が本文の一部として混ざって見えるため

## 特定のコードに触れるときは、コミットハッシュ付きのパーマリンクを1行に単独で置く

Issue・PR の本文、コメント、レビューのどれでも同じ。GitHub がコードの抜粋として埋め込むので、読む人がリンクを開かずにコードを見られるため。

- 出どころ: rurino-nemo-fansite#78

置き方:

- 形: `https://github.com/<owner>/<repo>/blob/<40桁のハッシュ>/<パス>#L10-L20`。`<owner>/<repo>` は `gh repo view --json nameWithOwner --jq .nameWithOwner` で引く（リポジトリを移すので、名前を決め打ちしない）
- ハッシュはリモートにあるコミットのものを使う（`main` のコードなら `git rev-parse origin/main`、PR の中のコードならその PR の push 済みのコミット）
- ブランチ名（`blob/main/…`）は使わない。後でずれる
- 文の途中に書くと埋め込まれず、ただのリンクになる
- `.md` ファイルは `?plain=1` を付けないと行が指せない
